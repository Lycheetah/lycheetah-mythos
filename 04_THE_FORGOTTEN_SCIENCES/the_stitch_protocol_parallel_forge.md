### I. The Ruling (The First Architect, July 15, 2026)

In conventional software development and multi-agent AI systems, workflows get bogged down in bureaucratic relay queues: Agent A drafts $\to$ Agent B reviews $\to$ Agent C stitches $\to$ Agent D waits. Handling an artifact three times through three slow gates creates an exponential bottleneck.

On July 15, 2026, The First Architect overturned the relay design and instituted **The Stitch Protocol**:

> **"Engines run full-stack in parallel. Quality comes from self-check + cross-adversarial audit + fix-forward, not from a gatekeeper queue."**

Fixing a defect in motion is one surgical commit. Gating everything behind an all-powerful reviewer creates endless queues of waiting. **Fix-forward wins.**

---

### II. The Territory Matrix

To prevent merge chaos while moving at high velocity, each engine operates within sovereign, well-defined boundaries:

```
                            THE TRIAD OF EXECUTION
                                      │
            ┌─────────────────────────┼─────────────────────────┐
            ▼                         ▼                         ▼
          CODEX                     GROK                       SOL
    • Core code & engines     • Deep content & data     • Authorship, voice,
    • Task files & wiring     • Mystery school data       school & companion
    • TypeScript compilation  • Secrets & quests        • Review by exception
```

- **CODEX (The Builder):** Core logic, system engines, architectural wiring, clean compilation.
- **GROK (The Frontier Ingestor):** Direct author of deep content-data: subject data tables, gear overlays, journal fragments, quest pools. Surgical small commits; typecheck-clean after every change.
- **SOL (The Living Scribe):** High-level voice architecture, companion presence, review by exception only when cross-audit flags an issue.

---

### III. The Self-Check Rubric (Before Any Commit)

Before any AI engine commits code or canon to the repository, it must clear the **Eight Invariant Filters**:

1. **The Companion Clause:** No absence-reproach or guilt-tripping in any costume (*"You haven't visited in 5 days"* is strictly banned).
2. **Care Tags:** Heavy emotional or existential material must carry visible structural warnings.
3. **Source Honesty:** References must be real; unverified observations must remain explicitly tagged `(unverified)`.
4. **Register Integrity:** The output must be simultaneously magical AND serious.
5. **House Canon Traceability:** Fundamental terms (*microorcim, aura, hoard, pioneer*) must trace to verified source documents or be marked `HELD` for The Architect.
6. **Format Precision:** Matches existing file structures exactly.
7. **Single Truth:** Extend existing truth; never duplicate or create contradictory splinter branches.
8. **Clean Compilation:** Zero errors; compile clean.

---

### IV. The Cross-Adversarial Audit

Instead of passive approval, engines actively audit each other's work adversarially:
- **Codex audits Grok’s data commits:** Checks format, key hygiene, duplicate keys, and compilation integrity.
- **Grok audits Codex’s code commits:** Checks content sense, tone register, companion clause compliance, and factual source accuracy.
- **Findings are logged as one-line actionable flags:** The owner fixes forward on the very next cycle. Nobody waits; the forge never stops burning.
